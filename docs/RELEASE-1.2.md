## Зарегистрированные сотрудники

В навигации администратора добавлен отдельный пункт «Сотрудники». Он показывает реальные аккаунты из Supabase Auth: ФИО, email, дату регистрации, подтверждение почты, роль и доступ. Предварительно разрешённые email без аккаунта сюда не попадают. Зарегистрированные аккаунты без разрешения отображаются с пометкой «Не предоставлен».

Есть поиск по ФИО/email и страницы по 50 записей. Кнопка «Изменить роль / доступ» открывает форму, где администратор выбирает «Администратор» или «Сотрудник» и включает/отключает доступ. Свою роль или доступ изменить нельзя. Изменение роли проверяется сервером, сохраняется через существующую функцию save_member и попадает в журнал. Понижение роли начинает действовать при следующем серверном запросе; открытый интерфейс обновляется при обновлении расписания.

Список аккаунтов доступен только действующему администратору с подтверждённой почтой. Секретные поля Auth, пароли и токены не возвращаются. Не путайте список реальных регистраций со списком предварительно разрешённых email в «Управлении».

## Обновление работающей базы

1. Если база уже версии 1.1, выполните `supabase/004_registered_members.sql` в SQL Editor. Таблицы и брони не удаляются.
2. Если база версии 1.0, сначала выполните `003_release_1_1.sql`, затем `004_registered_members.sql`.
3. Для новой базы: `001_schema.sql`, `002_retention.sql`, `003_first_admin.sql` с вашей почтой, затем `004_registered_members.sql`.
4. Обновите файлы сайта. **Сохраните свои значения config.js, если Supabase уже подключён**: поставляемый config.js содержит пустые параметры демонстрации.

Нельзя получить реальные регистрации на одном GitHub Pages без подключения общей базы. В демонстрации новый раздел содержит явно условные аккаунты и сохраняет изменения локально.

## Проверки

- 36 основных тестов пройдены, включая HTTP-сервер и правила бронирования.
- Существующие SQL/DOM-сценарии и регрессии сохранения пройдены.
- Новые серверные проверки: сотруднику и анониму список недоступен; разрешённый email без аккаунта не считается регистрацией; поиск и страницы 50+8; повышение даёт административный API; понижение и отключение немедленно отзывают его; самопонижение и неподтверждённый аккаунт не обходят проверку.
- Новые DOM-проверки: бренд банка, отсутствие большого баннера, отдельное административное меню, список, поиск, повышение/понижение и прямое открытие трёх экранов.
- Локальный браузерный канал вернул таймаут соединения с 127.0.0.1. Поэтому эти проверки не выдаются за визуальную приёмку браузером или за испытания реальной облачной базы.
