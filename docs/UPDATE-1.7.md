# Обновление Roomly 1.7

1. Распакуйте архив и загрузите его содержимое в корень репозитория roomly с заменой файлов. Существующий config.js сохраняйте. Не загружайте внешнюю папку архива вместо содержимого.
2. В Supabase → Edge Functions → create-employee → Code замените содержимое handler.mjs файлом supabase/functions/create-employee/handler.mjs из этого обновления. Нажмите Deploy. Название функции остаётся create-employee; она теперь обслуживает и создание аккаунта, и смену пароля администратором. index.ts менять не требуется. Настройку Verify JWT оставьте выключенной: проверка токена и текущих прав администратора выполняется самой функцией.
3. В настройках Supabase Authentication для Email/паролей установите Minimum password length = 6. В Password requirements не требуйте обязательного сочетания букв, цифр и спецсимволов. Тогда допустимы и только цифры, и только буквы, и их сочетания. Если включена проверка утёкших паролей, конкретный распространённый пароль всё ещё может быть отклонён. Существующие пароли не меняются. [Документация настроек паролей](https://supabase.com/docs/guides/auth/password-security).
4. После успешной публикации GitHub Pages обновите сайт Ctrl+F5.

## Изменения

- У сотрудников убрана кнопка смены своего пароля. Администратор сохраняет её в своём профиле.
- Сотрудники → Изменить роль / доступ → Изменить пароль: отдельная форма меняет пароль выбранного аккаунта по его Auth ID, не меняя роль, блокировку, email или бронирования. Несохранённые изменения роли не применяются при переходе к паролю.
- Новые и изменяемые пароли: 6–128 символов. Вход допускает существующие пароли без изменения.
- Во всех полях паролей есть «Показать / Скрыть»; изначально пароль скрыт.
- Удалены повторный блок «Доступ сотрудников» в Управлении и кнопка обновления в шапке. Автоматическое обновление данных сохранено.
- В подписях раздела сотрудников используется Email без упоминания телефона. Старые данные аккаунтов не удаляются; ограничение только доменом gmail.com не вводилось.

Удаление кнопки у сотрудника относится к интерфейсу Roomly. Штатный Supabase Auth API изменения собственного пароля не отключается этим обновлением. Административная смена чужого пароля защищена проверкой действующей роли admin на сервере.

## Проверки

Пройдены проверки синтаксиса, сборка, тесты API и серверной функции, DOM-тесты интерфейса: отсутствие кнопок у сотрудников, создание аккаунта с шестизначным паролем, переключение видимости, административная смена пароля, запрет сотруднику менять чужой пароль, сохранение ролей и блокировок, отсутствие дублирующего блока и регрессия бронирования. Вызовы Supabase в этих тестах имитируются; живые пароли не менялись.

После развёртывания проверьте на тестовом сотруднике создание аккаунта и смену пароля, затем вход в приватном окне. Новых SQL-миграций нет.
