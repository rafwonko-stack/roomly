# Обновление Roomly 1.8: удаление аккаунта

В разделе «Сотрудники» у правого края таблицы появился столбец «Удаление» с кнопкой «Удалить аккаунт». Удаление подтверждается в отдельном окне и выполняется серверной функцией create-employee: аккаунт удаляется из Supabase Authentication, а запись о его роли и доступе — из таблицы members.

## Как обновить

1. Загрузите файлы из архива в корень репозитория roomly с заменой одноимённых файлов. Папки сохраняются. config.js не трогайте, его в архиве нет.
2. В Supabase → Edge Functions → create-employee → Code замените содержимое handler.mjs файлом supabase/functions/create-employee/handler.mjs из архива и нажмите Deploy. index.ts не меняется. Verify JWT оставьте выключенным. Без этого шага кнопка покажет ошибку, и ничего не удалится.
3. После успешного деплоя GitHub Pages (вкладка Actions) обновите сайт через Ctrl+F5.

SQL-миграции не нужны.

## Что делает удаление

- Только действующий администратор (права проверяются на сервере).
- Свой аккаунт удалить нельзя, ни кнопкой, ни запросом.
- Сначала удаляется пользователь в Authentication, после этого очищается запись в members, чтобы будущий аккаунт с тем же email не унаследовал старую роль.
- Бронирования и журнал действий удалённого сотрудника сохраняются.
- Действие необратимо. Пользователь сразу теряет возможность войти.

## Проверка

Создайте тестовый аккаунт, удалите его кнопкой и убедитесь, что он исчез из Supabase → Authentication → Users и из списка сотрудников.
