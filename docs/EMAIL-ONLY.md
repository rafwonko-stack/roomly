# Roomly 1.5 — аккаунты создаёт администратор

В приложении остался только Email + пароль. Самостоятельная регистрация, Google, телефонный вход, SMS и привязка телефона удалены. Смена пароля и восстановление по email сохранены. База, аккаунты, роли, брони и config.js при обновлении не менялись.

## Один раз в Supabase

1. В Authentication → Sign In / Providers (или General Configuration) выключите **Allow new users to sign up**. Оставьте Email Provider включённым.
2. Отключите Phone и Google Provider, если они включены. Удаление кнопок сайта само по себе не запрещает прямые запросы к Auth API.
3. Для восстановления пароля оставьте SMTP и Site URL / разрешённый Redirect URL `https://rafwonko-stack.github.io/roomly/` настроенными.

Настройки облака не применялись автоматически. Документация: https://supabase.com/docs/guides/auth/general-configuration

## Как выдавать аккаунты

1. Supabase → Authentication → Users → Add user → Create new user. Укажите настоящий email сотрудника и индивидуальный пароль. Подтвердите email при административном создании (Auto Confirm User, если эта опция доступна), иначе существующая проверка доступа потребует подтверждения адреса.
2. Передайте сотруднику email и пароль. Создание аккаунтов выполняйте в Supabase, не в браузерном коде Roomly. Административные secret/service_role ключи в сайт не добавляйте.
3. Новый аккаунт получает employee через существующий триггер. При необходимости измените роль и доступ в «Сотрудники». Если на вашей старой базе триггер не установлен, добавьте email сотрудника в список доступа Roomly; сама запись доступа не создаёт Auth-аккаунт или пароль.
4. Сотрудник входит на сайт. Пароль можно изменить в профиле. ФИО при отсутствии в аккаунте вводится в форме бронирования.

Существующие аккаунты не удаляются. Для ранее созданного телефонного аккаунта добавьте подтверждённый email и пароль к тому же Auth-пользователю административными средствами, сохранив ID; не создавайте дубль, иначе история останется у старого аккаунта.

## Загрузка обновления

Содержимое архива загрузите в корень существующего репозитория с заменой. index.html должен лежать рядом с assets. Свой config.js сохраните. Новые SQL-миграции для этого обновления не нужны; старые миграции повторно не запускайте. Дождитесь публикации GitHub Pages, затем Ctrl+F5.

Файл tests/phone.test.mjs и старый phone-ui.mjs заменены пустыми заглушками для удаления устаревших исполняемых тестов при загрузке архива. Их можно удалить из репозитория.

Проверены: отсутствие регистрации и других способов входа, Email-вход, восстановление пароля, работа интерфейса и сохранение бронирования. Реальные настройки Supabase и доставка писем требуют проверки владельцем.
