# Roomly 1.1 — быстрый старт

## Показ руководителю

Откройте `presentation.html` и нажмите «Начать демонстрацию». Сценарий на пять минут находится в [SHOWCASE.md](SHOWCASE.md). Все данные демонстрации условные и сохраняются в вашем браузере. Общая база без настройки Supabase не работает.

## Публикация

Загружайте **содержимое** папки проекта в корень репозитория. `index.html`, `presentation.html`, `config.js` и папка `assets` должны лежать рядом, без внешней папки Roomly-project. Для публикации из ветки: Settings → Pages → Deploy from a branch → main → /(root). Презентация доступна по адресу `/presentation.html`, приложение — по главному адресу.

Для альтернативной публикации через включённый `.github/workflows/pages.yml` выберите Pages → GitHub Actions. Не смешивайте способы. В существующем репозитории Roomly публикация работает из ветки, проверки вынесены в checks.yml.

## Общая база

1. Создайте проект Supabase под своим аккаунтом.
2. Для новой базы последовательно выполните `supabase/001_schema.sql`, `supabase/002_retention.sql` и `supabase/003_first_admin.sql`. В последнем замените заглушку на email первого администратора.
3. Для существующей базы 1.0 выполните **только** `supabase/003_release_1_1.sql`. Не запускайте создание таблиц заново. Для новой базы этот файл не нужен.
4. Включите Email/password, подтверждение email, пароль от 12 символов. Укажите адрес сайта среди разрешённых перенаправлений. Подключите почтовый транспорт и проверьте письма регистрации/восстановления пароля.
5. Укажите в `config.js` URL проекта и **публичный publishable/anon key**. Секретный service_role key и пароль БД не нужны сайту и не должны попадать в GitHub.
6. Зарегистрируйтесь на почту первого администратора, подтвердите её, войдите. Добавьте реальные залы и email сотрудников в разделе «Управление». Сотрудники регистрируются самостоятельно; автоматических приглашений нет.

После заполнения URL и публичного ключа автоматически включится настоящий вход. Переключение деморолей и сброс демоданных исчезнут. Демоброни не переносятся в рабочую БД.

## Перед запуском в офисе

- Подтвердите вместимость, оборудование, часовой пояс, список администраторов и сотрудников.
- В версии 1.1 сохранён шаг 30 минут. Противоречие с 15 минутами в ответах заказчика требует решения.
- В версии 1.1 контакты организаторов видят все допущенные сотрудники. Это правило также требует подтверждения.
- Проверьте два разных аккаунта в двух браузерах: создание/отмена, обновление расписания, конфликт одновременных броней, права сотрудника и администратора.
- Проверьте письма, выполнение очистки истории, целевые браузеры и реальную офисную нагрузку. Локальные тесты не заменяют приёмку облака.

## Для разработчика

`npm run build` пересобирает браузерный файл. `npm run check` проверяет синтаксис. `npm test` запускает основные проверки. `npm ci --prefix tests/integration` устанавливает только тестовые зависимости; затем `npm run test:integration`. `npm start` запускает локальный сервер на порту 4173. Конечному пользователю Node.js не нужен.

Изменения релиза и ограничения: [RELEASE-1.1.md](RELEASE-1.1.md).
