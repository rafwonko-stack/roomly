# Roomly 1.1

## Исправления после аудита

- Подтверждение успешной брони не пропадает при последующей ошибке обновления экрана. Повторять сохранение в этом случае не предлагается.
- Отмена брони и изменение зала/доступа также отделены от последующей загрузки данных.
- Устаревшая занятость открытой формы не блокирует запрос на сохранение. Решение принимает актуальная проверка в хранилище/БД.
- При отключении зала с отменой сервер сравнивает текущий список встреч с просмотренным администратором. Изменение списка откатывает всю операцию. Нужно закрыть и вновь открыть настройки, проверить новый список и повторить действие.
- Сохранённые встречи отключённого зала остаются видны в дневном расписании, новые брони в нём недоступны.
- Обычный снимок загружает общий период от семи дней назад до тридцати дней вперёд, плюс личную историю. Общая история других сотрудников загружается по выбранной дате, а не за весь год сразу.
- Неуспешные попытки не меняют версию расписания и не вызывают лишнюю общую перезагрузку.
- Клиент отправляет версию редактируемой брони: устаревшая версия отклоняется сервером. При работе через старый сторонний клиент без версии эта дополнительная проверка не применяется.
- Администратор может исправить описание уже начавшейся встречи с сохранением её зала и временного интервала. Создание новой брони задним числом по-прежнему запрещено.
- Ошибки проверки полей залов и доступа локализованы, неизвестные серверные ошибки не выводятся пользователю на английском.
- Добавлены страница презентации, сценарий показа и новые демонстрационные встречи на завтра.

## Обновление базы

Новый проект: выполнить `supabase/001_schema.sql`, затем `supabase/002_retention.sql` по README.

Существующая база версии 1.0: выполнить только `supabase/003_release_1_1.sql`; повторно запускать создание таблиц из 001 нельзя. Миграция 003 обновляет функции, не удаляя брони и пользователей. Новая версия клиента должна использовать новую версию функций.

## Границы готовности

Демонстрация готова к показу. Рабочее облако не подключено без URL и публичного ключа проекта. Требуется проверка настоящих email-писем, задания очистки истории, четырёх целевых браузеров и реальной офисной нагрузки. Резервное копирование и возможности второго этапа не заявляются реализованными.

Шаг 30 минут, общая видимость контактов и часовой пояс Asia/Bishkek сохранены из исходной версии; неоднозначности ТЗ не считаются автоматически согласованными.
