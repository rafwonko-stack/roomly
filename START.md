# Запуск версии 1.3

## 1. Подключить Supabase

Создайте проект Supabase или используйте существующий проект Roomly.

Для НОВОЙ пустой базы в SQL Editor выполните по порядку:
1. supabase/001_schema.sql — таблицы, защита, функции и 10 начальных залов.
2. supabase/004_registered_members.sql — список зарегистрированных аккаунтов.
3. supabase/005_employee_registration.sql — автоматическая роль сотрудника.

Для СУЩЕСТВУЮЩЕЙ базы Roomly не запускайте 001 повторно. Выполните 003_release_1_1.sql, 004_registered_members.sql и 005_employee_registration.sql. Обновление не удаляет бронирования. Ранее назначенные роли и отключённые аккаунты сохраняются; зарегистрированные пользователи без записи доступа получат сотрудника.

Чтобы выполнить требование хранения истории за год, отдельно примените 002_retention.sql. Он удаляет только записи старше 365 дней, а не вчерашние встречи. Без этого задания автоматической очистки нет. История в интерфейсе ограничена годом.

В config.js впишите Project URL и публичный publishable/anon key. Пароль базы, secret key и service_role в файлы сайта не помещайте.

## 2. Настроить регистрацию и письма

В Supabase Authentication включите Email/password, разрешите новые регистрации и оставьте Confirm email включённым. Установите минимальную длину пароля 12 символов на сервере.

В URL Configuration укажите Site URL и разрешённый Redirect URL:
https://rafwonko-stack.github.io/roomly/

Подключите собственный SMTP в настройках Authentication для писем сотрудникам. Стандартный SMTP Supabase предназначен для тестирования и ограничивает адресатов участниками команды проекта. Настройки SMTP вводятся только в Supabase, не в config.js.
Документация: https://supabase.com/docs/guides/auth/auth-smtp
Адрес возврата: https://supabase.com/docs/guides/auth/redirect-urls

## 3. Назначить первого администратора

В supabase/003_first_admin.sql замените REPLACE_WITH_YOUR_EMAIL@example.com на ваш настоящий email целиком в нижнем регистре и выполните SQL. Затем зарегистрируйте этот адрес на сайте и подтвердите письмо. Если аккаунт уже существует, выйдите и войдите снова. Самый первый зарегистрированный пользователь НЕ получает администратора автоматически.

Далее новые аккаунты получают сотрудника. Администратор меняет роли в разделе «Сотрудники». Подтверждение email обязательно, даже если роль уже назначена.

## 4. Загрузить сайт в GitHub

Репозиторий: https://github.com/rafwonko-stack/roomly

Распакуйте архив. Загрузите его СОДЕРЖИМОЕ в корень репозитория. index.html, config.js и папка assets должны лежать рядом. Не загружайте дополнительную внешнюю папку с названием архива.

В Settings → Pages выберите Deploy from a branch → main → /(root), Save. Если используете включённый в проект workflow, выберите GitHub Actions вместо публикации из ветки. Не смешивайте два способа.

Адрес сайта: https://rafwonko-stack.github.io/roomly/
После успешного завершения публикации обновите страницу Ctrl+F5. Для сайта достаточно index.html, config.js, .nojekyll и assets; остальные файлы — исходники, миграции и проверки.

## 5. Приёмка перед запуском для сотрудников

1. Зарегистрируйте два настоящих адреса, подтвердите письма. Проверьте вход и восстановление пароля.
2. Администратором назначьте второму аккаунту администратора, затем верните роль сотрудника. Проверьте, что доступ к управлению исчез.
3. Создайте бронь и откройте сайт во втором браузере. Запись должна появиться после обновления, конкурирующий интервал — отклоняться.
4. Перезагрузите страницу. Переключите дату на вчера: прошлые записи остаются видимыми. «Мои встречи» показывает историю за год.
5. Проверьте реальные названия, вместимость и оборудование 10 начальных залов, измените их при необходимости.
6. Откройте сайт на телефоне, планшете и компьютере: навигация, выбор времени, регистрация и подтверждение брони.

Данные из старого локального деморежима не переносятся: они не являлись общей базой. Реальные записи существующего Supabase сохраняются.

Осталось подключить именно ваш облачный проект и SMTP. Эти действия требуют доступа владельца. Код не создаёт платные ресурсы и не публикуется в GitHub автоматически.
